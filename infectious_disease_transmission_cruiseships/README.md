# infectious_disease_transmission_cruiseships

This repository contains R scripts and input data for an agent-based model of infectious disease transmission on cruise ships. The model simulates passenger and crew interactions and disease progression to evaluate interventions (testing, masking, vaccination, isolation/quarantine, and sanitation practices) and outcomes over a voyage.

The sample workflow is configured for the case study on COVID-19 transmission on a standard cruise ship network with three initially infected individuals.

## Main Scripts

| File | Purpose |
| --- | --- |
| `R/functions.R` | Core model functions for agents, disease-state transitions, viral load, testing, masking, vaccination, quarantine, network creation, interactions, and voyage simulation. |
| `R/create_networks.R` | Builds demographic contact networks for standard, family, and senior cruise ship scenarios and initializes infected populations. |
| `R/run_single.R` | Runs each scenario in `Inputs/scenarios_sample.csv` once using serial computation and saves `Results/Simulation/results_sample_single.rdata`. |
| `R/run_parallel.R` | Runs the scenarios in `Inputs/scenarios_sample.csv` for a specified number of replications using R's `parallel` package and saves `Results/Simulation/results_sample_parallel.rdata`. |
| `R/scenario_analysis.Rmd` | Aggregates simulation outputs and creates summary outcome tables and plots. |

## Workflow

Clone the repository and set your working directory to the repository root:

```r
setwd("path/to/infectious_disease_transmission_cruiseships")
```

The simulation workflow has three main steps:

1. Prepare user-edited input files in `Inputs/`.
2. Create generated model inputs, especially cruise ship networks and initialized infected populations.
3. Run the simulation model either serially or with parallel replications.

## Simulation Inputs

The model uses both user-prepared tabular inputs and generated `.rdata` inputs. The tabular files define disease parameters, contact settings, ship configurations, demographics, and scenario interventions. The generated files contain R objects created by model functions, such as cruise ship contact networks and initialized agent populations.

| Input file | Format | Source | Used by | Purpose |
| --- | --- | --- | --- | --- |
| `Inputs/covid_parameters.csv` | CSV | User-created or user-edited | `R/create_networks.R`, `R/run_single.R`, `R/run_parallel.R` | Disease progression parameters, age-specific probabilities, state durations, and related COVID-19 assumptions. |
| `Inputs/network_parameters.csv` | CSV | User-created or user-edited | `R/create_networks.R`, `R/run_single.R`, `R/run_parallel.R` | Contact network assumptions, including network type, group inclusion proportions, minimum and maximum groups, and minimum and maximum contacts. |

## Step 1: Prepare User-Edited Inputs

Before generating networks or running simulations, review and edit the user-controlled input files. These files define the disease, ship population, contact structure, initial infections, and intervention scenarios.

### `Inputs/covid_parameters.csv`

This file contains the disease natural history parameters used by the agent-state transition functions. It controls how long agents remain in disease states and the probability that agents move from one state to another.

Columns:

- `Description`: plain-language description of the parameter.
- `Parameter`: parameter name used by the model, such as `Te`, `Tasym_rec`, `Tpre-sym`, `Tsym_rec`, `Phosp`, `Pdead`, or `Psym`.
- `AgeGroup`: age group for age-specific parameters, such as `0-12`, `13-17`, `18-64`, `65+`, or `General`.
- `Distribution`: type of distribution or estimate used.
- `Mean`: mean value or point estimate.
- `SD`: standard deviation, when relevant.
- `Notes`: optional notes about the parameter.

Edit this file when changing the pathogen, disease-state durations, symptom probabilities, hospitalization probabilities, mortality probabilities, or assumptions for age-specific disease severity.

### `Inputs/network_parameters.csv`

This file defines assumptions for contact networks and activity-specific interactions. It is used when creating networks and when simulating daily contacts.

Columns:

- `Scenario`: scenario identifier for the network parameter row.
- `Network Type`: contact or activity network, such as passenger dining, entertainment, nightlife, kids, crew food, housekeeping, or crew-passenger contacts.
- `Prop included`: proportion of the relevant population included in that network.
- `Min groups` and `Max groups`: minimum and maximum number of groups involved, where the network is group based.
- `Group proportions`: proportions used when drawing activity group structures.
- `Min contacts` and `Max contacts`: minimum and maximum number of contacts for individual contact networks.

Edit this file when changing contact intensity, activity participation, group mixing, crew work-contact structure, or assumptions about how many daily contacts occur in each network.

### `Inputs/scenarios_sample.csv`

This file defines the scenarios that are actually run by `R/run_single.R` and `R/run_parallel.R`. Each row is one simulation scenario.

Important columns:

- `Scenario`, `ID`, and `label`: scenario identifiers and labels.
- `CruiseShip`: name of the network object to simulate, such as `std_net`.
- `Initial`: name of the initialized population object, such as `initial_std_net_I3`.
- `Number of crew`, `Number of passengers`, and `Trip duration (days)`: ship size and voyage duration used by the scenario.
- Initial disease-state columns: initial exposed, symptomatic, asymptomatic, and recovered passengers and crew.
- Transmission probability columns: passenger, crew, activity-specific, and crew-passenger transmission probabilities.
- `Quarantine`, `Quarantine day`, `Quarantine trigger`, and `Decrease in prob transmission`: quarantine/isolation assumptions.
- Vaccination columns: vaccination status, selection method, coverage by age group, and effectiveness by age group.
- Testing columns: testing status, testing protocol, testing capacity, testing days, true positive rates, and true negative rates.
- Masking columns: masking status, masking selection, masking duration, passenger coverage, and crew coverage.

Edit this file when changing which scenarios are run, intervention packages, initial infection assumptions, transmission probabilities, testing protocols, vaccination scenarios, masking assumptions, quarantine assumptions, or the network and initial-population objects used by the simulation. The values in `CruiseShip` and `Initial` must match R objects that are loaded before the simulation loop runs.

### `Inputs/demographics_scenarios.xlsx`

This workbook defines passenger travel-group size and age-composition distributions. It is used by `R/create_networks.R` to create demographic networks.

Sheets:

- `standard`
- `senior`
- `family`

Columns in each sheet:

- `groupSize`: number of passengers in the travel group.
- `comb`: age composition for that group type.
- `freq`: frequency of that group type.

Edit this file when changing passenger age distributions, household/travel-party composition, group sizes, or when creating a ship population that is more family-oriented, senior-oriented, adult-oriented, or otherwise age-targeted.

### `Inputs/cs_input_for_network_setup.xlsx`

This workbook defines the ship-level setup information used by `R/create_networks.R` to create networks and initialized populations. The current `create_networks.R` workflow only uses the columns listed below.

Important columns:

- `Scenario`: setup row selected by the network and initialization functions.
- `Number of crew` and `Number of passengers`: ship population size.
- `Crew Groups of 1`, `Crew Groups of 2`, `Crew Groups of 3`, and `Crew Groups of 4`: crew cabin/group-size distribution.
- `Passenger - Recovered` and `Crew - Recovered`: number of passengers and crew initialized as recovered.
- `Passenger - Initial exposed`, `Passenger - Initial infected asymptomatic`, and `Passenger - Initial infected symptomatic`: initial passenger infection counts.
- `Crew - Initial exposed`, `Crew - Initial infected asymptomatic`, and `Crew - Initial infected symptomatic`: initial crew infection counts.

Edit this file when changing the ship size, crew grouping structure, recovered counts, or initial disease-state configuration used to create new network and initial-population objects.

## Adapting the Workflow

This workflow can be adapted to other pathogens that spread through human-human transmission. The current implementation and input names are COVID-19 focused, so pathogen changes should begin with the disease and intervention input files.

### Other Human-Human Transmitted Pathogens

To model another pathogen, review and update:

| File | What to change |
| --- | --- |
| `Inputs/covid_parameters.csv` | Disease-specific natural history parameters, including exposed duration, asymptomatic duration, presymptomatic duration, symptomatic duration, hospitalization duration, probability of symptoms, probability of hospitalization, and probability of death. |
| `Inputs/scenarios_sample.csv` | Pathogen-specific scenario settings, including initial infections, transmission probabilities, testing assumptions, vaccination assumptions, masking assumptions, quarantine assumptions, and intervention timing. |
| `Inputs/cs_input_for_network_setup.xlsx` | Initial disease-state assumptions used when creating initialized populations, especially the number of initially exposed, symptomatic, asymptomatic, and recovered passengers and crew. |
| `R/functions.R` | Review if the new pathogen does not fit the current COVID-style disease-state model. In particular, `getViralLoad()`, `convert_Ct_logGEML()`, and `getTransmissibilityFactor_new()` contain viral-load and Ct-based assumptions, and the state transition logic in `setAgentState()` assumes exposed, asymptomatic, presymptomatic, symptomatic, hospitalized, dead, recovered, quarantined, and removed states. |
| `R/scenario_analysis.Rmd` | Review labels, plot titles, saved filenames, and outcome definitions that refer to COVID-19. |

The same state structure can be used for pathogens where some states are not relevant by setting the corresponding input parameters to remove or shorten those states. For example, if a pathogen does not have an asymptomatic or presymptomatic period, represent those states through the disease parameters in `Inputs/covid_parameters.csv`, such as by setting the relevant transition probabilities or state durations to 0 as appropriate for the pathogen assumptions. Review `R/functions.R` only if the pathogen requires a different model structure, viral-load/transmissibility relationship, testing logic, or intervention mechanism than the current workflow supports.

After changing pathogen inputs, regenerate initialized populations if initial disease states or disease parameters changed:

```r
source("R/create_networks.R")
```

Then confirm that the simulation scripts load the regenerated network and initial-population objects.

### Other Ship Configurations

To model a different ship configuration, such as a larger ship, different crew structure, larger passenger travel groups, or a population with a specific age distribution, review and update:

| Order | File | What to change |
| --- | --- | --- |
| 1 | `Inputs/demographics_scenarios.xlsx` | Define the passenger travel-group size and age-composition distribution for the ship population. Update this first when representing larger passenger groups, a senior-heavy ship, a family-heavy ship, or another age-targeted population. |
| 2 | `Inputs/network_parameters.csv` | Define contact-network assumptions for activity and work networks, including the proportion included, minimum and maximum groups, group proportions, and minimum and maximum contacts. Update this after the demographic structure if the new ship has different interaction patterns. |
| 3 | `Inputs/cs_input_for_network_setup.xlsx` | Define ship-level inputs used during network creation and initialization, including number of passengers, number of crew, crew cabin group proportions, recovered counts, and initial disease states. |
| 4 | `R/create_networks.R` | Run this script after updating Steps 1-3. It reads the edited `Inputs/demographics_scenarios.xlsx`, `Inputs/network_parameters.csv`, and `Inputs/cs_input_for_network_setup.xlsx`, then generates the ship network and initialized population objects. Review the script if adding new ship types beyond the current standard, family, and senior workflows. |
| 5 | `Inputs/scenarios_sample.csv` | Point each simulation scenario to the generated ship network object and initialized population object. The `CruiseShip` column should match the generated network object, such as `std_net`, and the `Initial` column should match the generated initialized population object, such as `initial_std_net_I3`. Also update passenger and crew counts, trip duration, transmission probabilities, and intervention settings for the simulation run. |
| 6 | `R/run_single.R` and `R/run_parallel.R` | Review if the generated `.rdata` filenames change. The sample scripts currently load `Inputs/std_net.rdata` and `Inputs/initial_std_net_I3.rdata`. |
| As needed | `R/functions.R` | Review before changing age group labels or crew structure. Several functions assume the age groups `0-12`, `13-17`, `18-64`, and `65+`, and crew are assigned to `18-64` in `makeDemographicNetwork()`. |

After changing ship configuration inputs, regenerate the network and initial-population objects:

```r
source("R/create_networks.R")
```

Then update or resave the generated `.rdata` files so the object names in `Inputs/scenarios_sample.csv` and the filenames loaded by `R/run_single.R` and `R/run_parallel.R` all match.

## Step 2: Create Generated Inputs

To regenerate cruise ship contact networks and initial infection configurations, run:

```r
source("R/create_networks.R")
```

This script reads:

- `Inputs/demographics_scenarios.xlsx`
- `Inputs/cs_input_for_network_setup.xlsx`
- `Inputs/network_parameters.csv`
- `Inputs/covid_parameters.csv`

and creates:

- `std_net`, `fam_net`, and `sen_net`
- initialized populations for standard, family, and senior cruise ship networks
- `Inputs/settings.rdata`

The generated `Inputs/settings.rdata` file stores all network and initialized population objects together. The current sample run scripts load `Inputs/std_net.rdata` and `Inputs/initial_std_net_I3.rdata` directly, so those files must exist before running the sample simulations.

If you regenerate inputs with `R/create_networks.R`, either:

- update `R/run_single.R` and `R/run_parallel.R` to load `Inputs/settings.rdata`, or
- save the specific generated objects using the filenames expected by the sample scripts.

For example:

```r
load("Inputs/settings.rdata")
save(std_net, file = "Inputs/std_net.rdata")
initial_std_net_I3 <- initial_std_3
save(initial_std_net_I3, file = "Inputs/initial_std_net_I3.rdata")
```

## Step 3: Run the Simulation Model

Both run scripts use the same core simulation function, `simulate_voyage_onerep()`, for each scenario in `Inputs/scenarios_sample.csv`. The difference is that `R/run_single.R` runs each scenario once, while `R/run_parallel.R` runs a specified number of replications and distributes those replications across parallel workers.

| Script | Computation style | Replications | Output |
| --- | --- | --- | --- |
| `R/run_single.R` | Serial | One run per scenario | `Results/Simulation/results_sample_single.rdata` |
| `R/run_parallel.R` | Parallel | `n_reps` replications per scenario | `Results/Simulation/results_sample_parallel.rdata` |

Run the serial workflow:

```r
source("R/run_single.R")
```

This reads:

- `Inputs/covid_parameters.csv`
- `Inputs/scenarios_sample.csv`
- `Inputs/network_parameters.csv`
- `Inputs/std_net.rdata`
- `Inputs/initial_std_net_I3.rdata`

and writes:

- `Results/Simulation/results_sample_single.rdata`

## Run Parallel Replications

To run the sample scenarios with multiple replications:

```r
source("R/run_parallel.R")
```

By default, `R/run_parallel.R` uses:

- `n_reps = 3` replications per scenario
- `num_cores = 7` worker processes

Adjust these values in the script for your machine and experiment size.

The parallel run writes:

```text
Results/Simulation/results_sample_parallel.rdata
```

To add or modify scenarios, edit `Inputs/scenarios_sample.csv`, confirm the referenced network and initial population objects are available, then rerun `R/run_single.R` or `R/run_parallel.R`.

## Outputs

Simulation outputs are saved in `Results/Simulation/` as `.rdata` files. Analysis outputs are saved in `Results/Analysis/` and include summarized state counts, outbreak results, isolated COVID outcomes, symptomatic outcomes, and scenario-level outcome summaries.

The `Results/Configuration/` folder contains example network configuration plots for passengers and crew.

## Analysis

The analysis notebook is:

```text
R/scenario_analysis.Rmd
```

It includes helper functions for:

- aggregating infections and disease states by day
- calculating cumulative exposed and symptomatic counts
- comparing outcomes across scenarios
- summarizing outbreaks, isolated cases, and final outcomes

Before knitting the notebook, confirm that the input result paths in the R Markdown file match the result files you want to analyze.

## Model Overview

At a high level, the model:

1. Creates passenger and crew agents with demographic attributes.
2. Assigns initial disease states and infection durations.
3. Simulates daily contacts through demographic and activity-based networks.
4. Updates disease progression across susceptible, exposed, asymptomatic, presymptomatic, symptomatic, quarantined, hospitalized, dead, recovered, and removed states.
5. Applies interventions such as vaccination, masking, testing, quarantine, and passenger removal.
6. Records passenger and crew histories for scenario-level analysis.

## Notes for Reproducibility

- Run scripts from the repository root so relative paths resolve correctly.
- Keep `Inputs/` file names stable unless you also update the scripts.
- Large `.rdata` result files can be regenerated from the scripts and input files.
- Random seeds are set in network initialization functions, but simulation results may still vary depending on workflow changes and parallel execution settings.
